# Согласованный план реализации

## Структура

В корне: index.html, styles.css, README.md; src/core.mjs — чистая обработка, src/app.mjs — файлы и DOM; tests/core.test.mjs — встроенный node:test; docs — спецификация и план. PO_Vibecoding_Task остаётся неизменной папкой оригиналов.

Запуск: `python3 -m http.server 8000 --bind 127.0.0.1`. Проверки: `node --test tests/core.test.mjs`.

## Модель и интерфейсы ядра

`parseDocument({name, text}, documentId)` возвращает тип, номера договоров, подписи, даты, абзацы и поля с доказательствами. ID назначается вызывающей стороной, не выводится из имени файла. Абзац хранит диапазон символов исходника, ID и точный текст. Поле содержит status (found/no-data/needs-review), value и evidence; доказательство содержит имя файла, ID абзаца и цитату.

Следующая итерация добавляет `buildContractView(documents, asOfDate)` и `filterContracts(contracts, {deliveryBefore})`. Сумма и срок выбираются независимо; неизвестные или конфликтующие основания не скрываются за старым значением. Неизменённое поле наследуется из предыдущего действующего документа. Связывание — по явному номеру договора, с диагностикой конфликтов и дубликатов.

## Проверки и риски

Первая итерация: шесть исходников; изменённые сумма/срок и новое имя файла; новый договор; отсутствующая сумма; конфликтующие факты; отрицание подписания; точность цитат и диапазонов, UTF-8/BOM/CRLF. Следующая: временная граница одного договора до/в/после даты вступления; изменение только суммы и только срока; проекты и письма; конфликт одинаковых дат; фильтр. Финальная ручная проверка — загрузка, смена даты, четыре ответа, фильтр и ссылки.

Риски: ограниченный словарь правил, ложное распознавание аванса/лимита/оплаты, конфликт документов, повреждённая кодировка. Использовать контекстные шаблоны и явные статусы; поддерживать UTF-8/BOM, остальные кодировки обозначить ограничением. Загруженный текст выводить через textContent.
